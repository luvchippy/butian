# 补天作战手册

## 平台规则（先搞懂，不然白干）

补天（butian.net）的白帽流程：

1. 注册 → 实名认证（必须，不然不能提漏洞）
2. 进入「公益SRC」或「企业SRC」，看目标列表
3. **每个目标都有明确的资产范围**（通常写「主域名及子域名」或列具体域名）
4. 挖到漏洞 → 提交 → 厂商确认 → 定级 → 发赏金/积分

关键概念：

| 概念 | 意思 |
|---|---|
| 公益SRC | 厂商没给钱的，只给积分/证书。练手用 |
| 企业SRC | 有赏金的，按危害等级给钱 |
| 资产范围 | 你能测的域名/IP白名单。**超出即违规** |
| 重复漏洞 | 别人先交了，你没钱。所以要快 |
| 定级 | 严重/高危/中危/低危，直接决定赏金 |

## 赏金参考（2026年行情）

| 等级 | 典型漏洞 | 公益SRC | 企业SRC |
|---|---|---|---|
| 严重 | RCE、SQL注入拖库、支付逻辑 | 积分+证书 | 5000-50000 |
| 高危 | 未授权访问、越权、SSRF打内网 | 积分 | 1000-10000 |
| 中危 | 存储XSS、CSRF、信息泄露 | 积分 | 200-2000 |
| 低危 | 反射XSS、目录遍历、指纹泄露 | 积分 | 50-500 |

**新手现实**：前 20 个提交，能确认 3-5 个就算不错。别指望第一个月赚钱。

## 选目标的三个判据

打开补天目标列表，按这个顺序筛：

1. **资产范围大的** —— 写了「主域名及所有子域名」的，等于给你一片森林。只列 3 个域名的，收益低。
2. **老系统多的** —— 制造业、地方政府、传统企业、教育机构。Java SSH 框架、Struts2、老版本 OA 特别多。
3. **新上线的** —— 刚改版、刚上云的，业务逻辑漏洞多，没人测过。

避开：金融、支付、大型互联网主站。这些有专门安全团队，你打不动，还容易被封 IP。

## 提交前自检清单

- [ ] 这个域名在平台资产范围里吗？（截图保存范围页面）
- [ ] 漏洞能稳定复现 3 次以上吗？
- [ ] 复现步骤写清楚了吗？（审核员要 3 分钟内复现）
- [ ] 敏感数据打码了吗？
- [ ] 有没有下载/修改/删除任何数据？（有就立刻停止，别提交）
- [ ] 这个漏洞类型厂商收吗？（有的厂商明文不收 Self-XSS、不收无危害信息泄露）

## 常见被拒原因

| 被拒理由 | 真实原因 | 怎么避免 |
|---|---|---|
| 重复 | 别人先交了 | 挖偏门资产，别打主站 |
| 无危害 | 信息泄露但没有敏感数据 | 证明能进一步利用 |
| 不在范围 | 打了范围外域名 | 提交前对一遍范围 |
| 需登录 | 漏洞点需要账号，但危害不足 | 用两个账号证明越权 |
| 已修复 | 厂商自己发现了 | 正常，换目标 |
| 环境问题 | 测试环境不算 | 打生产环境 |
